# Actual product, one device per recording

Logline: Four familiar devices show E-JUAN's main tasks through real interactions.

Considered: a promotional montage; narrated slides; continuous device-framed walkthroughs. Selected the last because the user explicitly requested recordings and retained mockups. The product owns the phone/tablet/monitor shells and its actual concern, report, stock and message objects. Existing visuals remain intact; only capture-session framing and short feature captions are added.

Each recording has nine eight-second chapters followed by a clean stop on its last working screen. This is a 120 BPM, four-bar chapter grid; real typing and UI responses are allowed within each chapter. The device is the continuous visual object. No cuts, zooms, blur, audio or outside footage. Each short caption identifies the current action; no added clinical or deployment claims.

Citizen: Home → Ask Juan → four questions → guidance/center → center stock → medicines → saved report → emergency information → filtered center search.

SMS: routine conversation → clinic details → visit reference → STOP → START → urgent example → emergency status → EMERGENCY reply → information disclosure.

BHW: access screen → practice dashboard → fictional resident → symptom report → saved local result → records list → local sync simulation → offline work → retained records.

LGU: demo access → overview → review report → facilities → stock operation → map → trends → BHW monitoring → aggregate export.

Review gates: complete mockup in every sampled frame; actual interaction and resulting state; no clipped primary controls; no blank lead-in or trailing browser UI; all four durations >=60 seconds; full decode; correct dimensions; H.264; yuv420p; BT.709; retained prototype/demo notices; source hashes unchanged. Two review passes: framing/screenshots before capture, then encoded contact sheets and playback.
